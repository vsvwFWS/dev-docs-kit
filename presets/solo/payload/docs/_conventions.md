# 開発ドキュメントの共通規約

文書を編集するときの共通原則です。Markdownを正本とし、人間が全体像と現行仕様を理解でき、AIが必要な情報を選んで保守できる構成を維持します。

## 共通原則

- 外部から見える振る舞い、重要な制約・判断、繰り返し使う手順を優先し、必要な文書だけ段階的に作ります。軽微な修正ごとに一式を作りません。
- 同じ説明は一か所を正本とし、ほかはリンクします。作業ログを現行仕様の代わりにしません。
- 現行の合意済み仕様と変更案を区別します。合意済み変更・実装の不具合・意図不明の差分を分け、不具合や不明点に合わせて仕様を変更しません。
- 不明な事項・推測は本文の「未確認事項」に明示し、HTMLコメントだけに隠しません。根拠となるコード・テスト・資料へリンクします。
- 用語や命名は既存の用語集（あれば `glossary.md`）に従い、新しいドメイン概念を導入したら用語集へ追記します。
- 冒頭で対象・要点・適用範囲を説明し、抽象的な説明には具体例を添えます。テンプレートの該当しない項目・例は削除し、空欄を埋めるために説明を創作しません。
- 1ファイル1テーマを目安とし、300行を超えたら分割を検討します。親文書に全体像の要約と詳細へのリンクを残します。
- 内容変更時にupdatedを当日へ更新します。編集日は内容の正しさや検証済みであることの証明には使いません。

## 作業に応じて読む詳細

詳細を一括で読み込まず、今回の作業に必要な資料・節だけを参照します。同じ作業中に既に確認した規約を繰り返し読む必要はありません。

| 資料 | 読む条件 |
|---|---|
| [メタデータとリンク](./_guides/metadata.md) | 新規作成、メタデータ・本文リンク・関連IDの編集、該当する検証エラー |
| [文書の種別・配置・状態](./_guides/document-types.md) | 新規作成、状態変更、仕様と計画の整理。対象種別の節を参照 |
| [図・画像・表](./_guides/diagrams.md) | 図・画像・大きな表を作成または変更 |
| [既存文書の取り込み](./_guides/adoption.md) | 既存文書を取り込む初期整備・移行 |

テンプレートは新規作成や構成の見直し時に `docs/_templates/` の対象種別だけを参照します。[ビューアー連携契約](./_viewer-contract.md) は連携の実装・調査時だけ参照します。JSONスキーマや検証スクリプトのソースは通常の文書編集で読む必要はありません。

## 更新後の検証

文書の作成・更新後は以下を実行し、目次と履歴を同期してエラーゼロを確認します。

```bash
node .agents/skills/docs-sync/scripts/docs_lint.mjs --index
```

エラーは修正して再実行し、警告は内容を確認して未解決なら理由を報告します。このコマンドは構造を検証し、リンクの自動修復や内容の正しさの保証は行いません。AIは根拠・用語・重複・仕様との差分を確認し、人間は目的・判断・仕様が意図に合うか確認します。
