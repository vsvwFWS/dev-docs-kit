# 開発ドキュメントの初期整備

`docs/_conventions.md` を読み、README・既存docs・ルート設定・主要コードの有無を確認します。既存の文書やユーザーの説明を優先し、正本・重複・未確認事項を整理します。

## コードがまだない場合

会話や既存資料から目的・利用者・主要な利用シナリオ・非対象を整理します。判断に必要な情報が不足するときだけユーザーに確認します。

indexとoverviewから始め、未決定の構成・技術・用語を確定情報として生成しません。概要の未確認事項は本文で見える形にし、未確認の初版はdraftにします。

## 既存コードがある場合

パッケージ定義、エントリーポイント、主要なモデル・処理を調査し、既存文書と照合します。コードから判断できない目的・背景は推測と明示します。

overviewを整え、構成・境界の理解が必要ならarchitecture、用語の整理が必要ならglossaryを作ります。必ず3文書を生成する必要はありません。新機能や予定変更はplanに分けます。

## 既存文書の取り込み

- 既存ファイルは自動で一括上書き・移動しません。依頼範囲に従い、採用・統合する文書と当面保持する文書を整理します。
- 取り込む文書はメタデータ・状態・リンクを整えます。元の意味を変えず、重複する説明の正本を決めます。
- 当面対象外の通常Markdownは `docs/_config.json` のexcludedFilesへ相対ファイルパスで個別登録します。既存設定を保持し、取り込んだファイルだけ一覧から外します。
- indexは入口として取り込むため除外できません。既存の本文を保持し、フロントマターと自動一覧のマーカーを統合します。

## 入口と確認

`docs/_templates/` を使い、存在する文書だけをindex冒頭の目的別案内にリンクします。overviewの機能一覧から仕様へ、仕様から必要な設計理由や手順へ進めるようにします。

```bash
node .agents/skills/docs-sync/scripts/docs_lint.mjs --index
```

作成・統合した文書、対象外にした文書、本文の未確認事項、確認した根拠を報告します。Lint成功だけで内容の正しさを保証しません。
