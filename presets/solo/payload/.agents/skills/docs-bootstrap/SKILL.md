# 開発ドキュメントの初期整備

[共通規約](../../../docs/_conventions.md)を入口に、README・既存docs・ルート設定・主要コードの有無を確認します。既存の文書やユーザーの説明を優先し、正本・重複・未確認事項を整理します。

詳細資料を一括で読み込まず、作成・編集する文書に必要な資料・節だけを読みます。同じ作業中に既に確認した規約を繰り返し読む必要はありません。

## コードがまだない場合

会話や既存資料から目的・利用者・主要な利用シナリオ・非対象を整理します。判断に必要な情報が不足するときだけユーザーに確認します。

indexとoverviewから始め、未決定の構成・技術・用語を確定情報として生成しません。既存文書の取り込みがなければ取り込みガイドは読みません。

## 既存コードがある場合

パッケージ定義、エントリーポイント、主要なモデル・処理を調査し、既存文書と照合します。コードから判断できない目的・背景は推測と明示します。

overviewを整え、構成・境界の理解が必要ならarchitecture、用語の整理が必要ならglossaryを作ります。必ず3文書を生成する必要はありません。

## 既存文書を取り込む場合

既存文書を扱う初期整備・移行時だけ [取り込みガイド](../../../docs/_guides/adoption.md) を読み、対象外一覧と既存目次の統合を含めて進めます。

## 作成・編集と確認

新規作成では共通規約からメタデータガイドと種別ガイドの対象節へ進みます。既存文書は変更するメタデータ・リンク・状態・図などに該当する詳細だけを確認します。テンプレートは新規作成や構成の見直し時に `docs/_templates/` の対象種別だけを参照します。

共通規約と対象種別の案内に沿って入口を整え、更新後の検証を実行します。作成・統合した文書、対象外にした文書、本文の未確認事項、確認した根拠、検証結果を報告します。
