# ドキュメントの同期・検証

## 依頼を分ける

検証だけの依頼では、下記「構造の検証と報告」へ進みます。コード差分の調査や規約・テンプレートの読み込みは不要です。エラーが出た場合だけ該当する規約を確認します。

実装後の影響確認では、git status / git diffと、対象タスクで変更したコミットや計画を確認します。`docs/index.md` から関連する現行仕様・構成・用語・変更案を読みます。文書変更が不要なら、その判断と根拠を報告して終了します。規約・テンプレートの読み込みや文書更新・Lintを強制しません。

## 差分の判断

| 分類 | 対応 |
|---|---|
| ユーザー指示や計画に基づく合意済みの変更 | 実装・検証結果を確認し、現行文書に反映する |
| 現行仕様に反する実装の不具合 | 仕様を実装に合わせず、修正対象として報告する。修正作業は依頼範囲に従う |
| 合意・意図を確認できない差分 | planや対象文書の未確認事項に記録し、仕様の確定を保留してユーザーへ確認する |

「実装されている」という理由だけで仕様を変更しません。検証していないものを検証済みにしません。

## 編集が必要な場合

[共通規約](../../../docs/_conventions.md)を読み、作業に該当する詳細資料・節だけを参照します。詳細資料を一括で読み込まず、同じ作業中に既に確認した規約を繰り返し読む必要はありません。

- メタデータ・リンクの編集や新規作成：メタデータガイド。
- 状態変更、仕様と計画の整理、新規作成：種別ガイドの対象種別の節。plan完了やADRの置き換えも対象です。
- 図・画像・大きな表の変更：図表ガイド。

変化した内容だけを正本へ反映します。テンプレートは新規作成や構成の見直し時に `docs/_templates/` の対象種別だけを参照します。対象外の既存文書を依頼範囲を超えて取り込みません。更新後は共通規約の検証を行います。

## 構造の検証と報告

```bash
node .agents/skills/docs-sync/scripts/docs_lint.mjs --index
```

エラー時は[共通規約](../../../docs/_conventions.md)の案内から該当詳細へ進み、修正して再実行します。警告は内容を確認し、未解決なら理由を報告します。ビューアー等への構造化出力は `--json` を追加します。連携の実装・調査時だけ [ビューアー連携契約](../../../docs/_viewer-contract.md) を参照します。

反映した変更、実装の不具合・未確認事項、実行した検証を報告します。Lintは構造の確認であり、本文の正しさや人間の合意の保証ではありません。
