# ドキュメントの同期・検証

## 差分の判断

git status / git diffと、対象タスクで変更したコミットや計画を確認します。`docs/index.md` から関連する現行仕様・構成・用語・変更案を読みます。

仕様と実装の違いを次のように分類します。

| 分類 | 対応 |
|---|---|
| ユーザー指示や計画に基づく合意済みの変更 | 実装・検証結果を確認し、現行文書に反映する |
| 現行仕様に反する実装の不具合 | 仕様を実装に合わせず、修正対象として報告する。修正作業は依頼範囲に従う |
| 合意・意図を確認できない差分 | planや対象文書の未確認事項に記録し、仕様の確定を保留してユーザーへ確認する |

「実装されている」という理由だけで仕様を変更しません。検証していないものを検証済みにしません。

## 更新する内容

- spec：確認した現行の振る舞いと継続的な受け入れ条件。変更案はplanに保持します。
- architecture / guide / glossary：変化した責務・境界・処理の流れ・手順・用語だけを更新します。
- plan：変更前後、実装の進捗、実行した検証と結果、未実施項目、現行文書への反映状況を記録します。
- ADR：採用した判断と実装状況を混同しません。判断変更は新ADRで記録します。

計画の作業・必要な検証・文書反映が完了したらdoneにして `docs/plans/archive/` へ移動します。未解決の差分は解消または明示的に別作業へ引き継ぎます。移動元へのリンクと、移動した本文内の相対リンクの両方を更新します。

変更文書のupdatedを当日に更新します。正本の重複や用語の揺れを確認し、必要に応じてoverviewの機能一覧とindex冒頭の案内も更新します。対象外の既存文書を無断で取り込みません。

## 構造の検証と報告

```bash
node .agents/skills/docs-sync/scripts/docs_lint.mjs --index
```

エラーは修正して再実行します。警告は内容を確認し、未解決なら理由を報告します。ビューアー等への構造化出力は `--json` を追加します。

報告は「反映した変更」「実装の不具合・未確認事項」「実行した検証」に分けます。Lintは構造の確認であり、本文の正しさや人間の合意の保証ではありません。
