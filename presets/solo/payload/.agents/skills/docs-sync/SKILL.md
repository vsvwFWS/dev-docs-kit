# `docs-sync` スキル（ドキュメント同期・検証）

このスキルは、コードの変更やドキュメントの編集後に、`docs/` 内の記述と実装の乖離をなくし、フロントマター・リンク・目次（`docs/index.md`）の整合性を検証します。

## 手順

### 1. 変更内容の把握
1. `git status` や `git diff` を確認し、今回変更されたコードやドキュメントを特定します。
2. `docs/index.md` を見て、今回の変更に関係する `spec`, `architecture`, `glossary`, `plan` を確認します。

### 2. ドキュメントの更新
- **機能仕様（`docs/specs/`）**: インターフェース、振る舞い、受け入れ条件のチェック状態を実装に合わせて更新します。
- **アーキテクチャ（`docs/architecture.md`）**: 新しいモジュールや外部依存、データフローの変更があれば反映します。
- **用語集（`docs/glossary.md`）**: 新しいドメインモデルや重要な識別子が増えた場合は追記します。
- **作業計画（`docs/plans/`）**:
  - 完了したステップのチェックボックス（`- [x]`）を更新し、作業ログを追記します。
  - **計画がすべて完了した場合**: フロントマターの `status` を `done` に変更し、ファイルを `docs/plans/archive/` ディレクトリへ移動します（本文中の相対リンクがある場合は階層が1つ深くなる点に注意）。
- 更新したすべてのファイルのフロントマターにある `updated` を当日の日付（`YYYY-MM-DD`）に更新します。

### 3. 目次（`docs/index.md`）の自動更新と Lint 実行

以下のスクリプトを実行し、`docs/index.md` の一覧を最新化するとともに、フロントマター・ID参照・相対リンクの検証を行います。

```bash
node .agents/skills/docs-sync/scripts/docs_lint.mjs --index
```

- JSON 形式で詳細な結果を取得したい場合は `--json` オプションを追加できます。
- **エラー（ERROR）が出た場合**: 必須項目の欠落、不正な `status`、存在しない `related` ID、またはリンク切れがあります。すべて修正して再度実行してください。
- **警告（WARN）が出た場合**: 長期間更新されていない `active` な `plan` などがあれば、アーカイブするか更新するかを判断してください。
