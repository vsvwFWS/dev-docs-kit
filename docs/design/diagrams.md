# 図表フォーマットの選定方針

AIエージェントが作成・更新しやすく、かつ人間が VSCode や専用ビューアーで閲覧・手直ししやすい図表フォーマットとして、用途別に以下の優先順位を採用します。

---

## 用途別推奨フォーマット一覧

| 用途 | 第一選択 | 理由・特徴 | 代替・補足 |
|---|---|---|---|
| **フロー図・シーケンス図・状態遷移図・ER図・簡易構成図** | **Mermaid**（Markdown コードブロック埋め込み） | ・AIエージェントが直接生成・編集しやすい<br/>・Git で行単位の差分（diff）を追える<br/>・GitHub や VSCode でそのままプレビュー可能 | 構文エラーを防ぐため、ノードのラベルに記号（`()`, `[]` など）を含む場合は必ずダブルクォート `["ラベル (補足)"]` で囲む |
| **複雑なアーキテクチャ図・レイアウトを人間が細かく調整したい図** | **`.drawio.svg`**（`docs/assets/` に配置し Markdown から画像参照） | ・実体は標準的な SVG 画像なので、GitHub・VSCode・ブラウザのどこでもそのまま表示できる<br/>・内部に Draw.io の編集データを保持しているため、VSCode の Draw.io Integration 拡張で直接 GUI 編集できる | AIによる直接編集には向かないため、AIが叩き台を作る場合は Mermaid を使い、人間が清書したい図のみ `.drawio.svg` にする |
| **小〜中規模の表（選択肢の比較、項目一覧など）** | **Markdown テーブル** | ・文書内で完結し、AIも人間もすぐに読める | 1セルが長文になる場合は、箇条書きやセクション分割に切り替える |
| **大規模な表・構造化データ定義（多数のエラーコード一覧、設定一覧など）** | **YAML / CSV**（別ファイルに分離し Markdown からリンク） | ・数百行の Markdown テーブルはトークン効率が悪く、差分も見づらい<br/>・構造化ファイルに分けることで、プログラムやビューアーから直接テーブル表示・検索ができる | 小規模なうちは Markdown テーブルで始め、50行を超えた段階で外部ファイル化を検討する |
| **画面キャプチャ・外部資料画像** | **PNG / WebP**（`docs/assets/` に配置） | ・UI の見た目などテキストで表現できない情報の記録 | AIは画像の差分を作成できないため、仕様の正本は必ずテキストで記述し、画像は補助資料として扱う |

---

## 採用しなかったフォーマットと理由

- **PlantUML**: 表現力は高いものの、レンダリングに Java または外部サーバーが必要になり、ローカル完結のプレビュー環境を作りづらいため見送り。
- **D2**: レイアウト品質は高いものの、VSCode や GitHub での標準サポートが Mermaid ほど普及していないため、現時点では見送り。
- **生の SVG / PNG のみの図**: 編集元データが失われ、後から人間もAIも修正しづらくなるため、必ず Mermaid または `.drawio.svg` を使用します。
