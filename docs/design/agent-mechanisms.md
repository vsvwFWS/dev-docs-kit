# エージェント機構の選定と役割分担（Codex / Antigravity CLI 対応）

AIコーディングエージェントに開発ドキュメントのルールとワークフローを定着させるため、Instruction file（`AGENTS.md`）、Skills（`.agents/skills/`）、および Node.js スクリプト（`docs_lint.mjs`）の3層構造を採用しています。

---

## 1. Codex と Antigravity CLI の共通仕様

両エージェントは以下の標準パスを共通して自動認識します。

| 種類 | パス | 読み込みタイミング |
|---|---|---|
| **プロジェクト常駐ルール** | `AGENTS.md`（リポジトリルート〜作業ディレクトリ） | セッション開始時・常時 |
| **ワークスペーススキル** | `.agents/skills/<skill-name>/SKILL.md` | 通常は `name` と `description` のみ認識。タスクが合致したとき、または明示的に呼ばれたときに本文を読み込む（Progressive Disclosure） |

この共通仕様に合わせることで、特定エージェント専用の設定ファイル（`.cursorrules` や個別 JSON 設定など）を増やさずに、単一のペイロードで両エージェントに対応できます。

---

## 2. 各機構の役割と採否理由

| 機構 | 採否 | 役割 | 判断理由 |
|---|---|---|---|
| **`AGENTS.md`** | ✅ 採用 | **入口・ルーティング**<br/>・`docs/index.md` から読む原則<br/>・どの場面でどのスキルを使うかの案内<br/>・最低限の禁止事項 | 常時コンテキストに入るため、詳細なテンプレート仕様や手順をここに書くとトークンを圧迫します。そのため「ルーティング役」に徹します。 |
| **`.agents/skills/`** | ✅ 採用 | **オンデマンドの手順書（Runbook）**<br/>・`docs-author`: 文書の新規作成・単独編集<br/>・`docs-sync`: 実装後の同期と lint 手順<br/>・`docs-bootstrap`: 新規・既存で入口と必要な初期文書を整備 | ドキュメント作成時や同期時など、必要な場面でのみ詳細な手順を読み込ませることで、普段のコーディング時のコンテキストを節約できます。 |
| **Node.js スクリプト (`docs_lint.mjs`)** | ✅ 採用 | **機械的な検証とインデックス生成**<br/>・フロントマターの必須項目・型・`type`×`status` 検証<br/>・ID 重複、関連 ID 参照、相対リンク切れの検出<br/>・`docs/index.md` の自動更新（`--index`） | フロントマターの抜け漏れやリンク切れを LLM の注意力だけに頼ると不安定になります。スクリプトで決定論的にチェックすることで構造の品質を確認します。本文の意味や仕様と実装の一致は別にレビューします。 |
| **MCP サーバー** | ⏸ 見送り | – | ローカルの Markdown ファイルの読み書き・検索はエージェント標準のファイルツールで十分高速に行えます。また、MCP の設定ファイルはエージェントごとに異なりリポジトリへの同梱だけで完結しづらいため、将来ビューアーと連携する高度な検索が必要になった段階で導入します。 |
| **Hooks** | ⏸ 見送り | – | エージェントごとに設定フォーマットや発火タイミングが異なりポータビリティが低いため、lint 実行は共通規約と検証スキルから案内します。 |

## 3. 編集時の規約を段階的に読む

読み込み経路は **AGENTS.md → 必要なスキル → 共通規約 → 作業に必要な詳細・テンプレート** です。管理ブロックには目次の確認、スキルの選択、実装へ無条件に仕様を合わせない原則だけを置きます。新機能への着手だけをdocs-authorの起動条件にはしません。

共通規約には全編集に共通する原則と更新後の検証を置き、メタデータ・種別と状態・図表・既存文書の取り込みは `docs/_guides/` に分けます。ルールの詳細は一か所を正本とし、スキルには判断条件と参照先、テンプレートには執筆を助ける短い補足を置きます。

docs-syncはまず影響を判断し、変更不要なら規約・テンプレートを読みません。検証だけならコマンドを実行し、エラーに応じて規約へ進みます。docs-bootstrapは既存文書を扱う場合だけ取り込みガイドを読みます。3スキルとも資料の一括読み込みや同じ作業中の再読を要求しません。

ビューアー連携契約は連携の実装・調査時に参照します。JSONスキーマと検証スクリプトのソースも通常編集の必読資料にはしません。

## 4. 将来のビューアー／エディターとのコード共有

検証スクリプト `docs_lint.mjs` は、以下の2つの顔を持つように設計されています。

1. **導入先リポジトリでそのまま動くゼロ依存 CLI**
   - Node.js の標準モジュール（`node:fs`, `node:path`, `node:url`）のみで実装されているため、Python や Go、Rust などのプロジェクトに導入しても `package.json` や `node_modules` を作る必要がありません。
2. **ビューアーから `import` できる ES Module**
   - `parseDocument`, `loadDocsGraph`, `validateDocs`, `generateIndexContent` などの関数を `export` しています。
   - `loadDocsGraph` は全ドキュメントのフロントマターを解析し、本文リンクと `related` / `supersedes` から **型付きedgesと逆リンク（`referenceBacklinks` / `backlinks` / `supersededBy`）を自動計算したグラフ構造** を返すため、Web ビューアーや VSCode 拡張機能のバックエンド処理としてそのまま利用できます。

CLIの `--json` はformatVersion: 1の連携契約を持ちます。Node.jsで読み込んだ結果をJSONでビューアーへ渡し、ブラウザーが直接ファイルシステム依存のモジュールをimportする前提にはしません。詳細は [配布する連携契約](../../presets/solo/payload/docs/_viewer-contract.md) を参照してください。
