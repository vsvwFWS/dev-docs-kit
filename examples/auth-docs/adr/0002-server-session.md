# サーバー側セッションの採用

対象はログイン状態の管理です。少人数サービスで、ログアウトや管理操作による失効を単純に扱えることを優先します。

## 比較と決定

| 選択肢 | 利点 | 負担 |
|---|---|---|
| クライアント保持トークン | リクエストごとのセッション参照を減らせる | 即時失効の仕組みが別途必要 |
| サーバー側セッション（採用） | 保存状態の削除で失効を管理できる | セッションストアの管理が必要 |

この判断の採用と実装完了は別です。現在の振る舞いは[ログイン仕様](../specs/login.md)に記録します。
